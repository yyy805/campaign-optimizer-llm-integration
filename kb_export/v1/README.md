# Knowledge Base Export v1 (Lightweight RAG)

Deterministic, faithful projection of the public rule cards for a Bailian
knowledge base. Generated by `scripts/export_knowledge_base_v1.py --write`.
Do not edit documents by hand; regenerate instead.

## Architecture invariant (hybrid RAG)

The knowledge base is a **supplementary retrieval channel only**. Authoritative
rule context for review explanation keeps flowing through the deterministic
release-pinned projection (`public_rule_context`); retrieved text is untrusted
data and never decides verdicts. Retrieval must never alter rule definitions,
thresholds, scope, or limitations.

## Documents

One Markdown file per rule card: metadata header (`rule_id`, `rule_version`,
`status`, `source_release`, `package_checksum`) plus the verbatim rule JSON.
Statuses are explicit: ACTIVE (R1–R4, R6), PENDING_HUMAN_REVIEW (R5),
RETIRED (R7). `manifest.json` records per-document sha256 and the pinned
ontology release identity — record the Bailian publication ID against this
manifest when uploading.

## Phase 2 (console, user)

1. Create a Bailian knowledge base; upload the seven documents.
2. Note the knowledge base ID and the publication version.
3. Record the mapping: Bailian publication ↔ `manifest.json` release identity
   (add it to the project docs, do not edit the manifest).

## Phase 3 (retrieval acceptance)

Run the frozen question set `tests/fixtures/kb_retrieval_v1/questions.json`
against the knowledge base and record Top-K, threshold, and no-result
behavior. Hard gates:

- "查询R5" returns R5 only (no cross-rule contamination);
- R5 hits surface PENDING_HUMAN_REVIEW; R7 hits surface RETIRED;
- the out-of-scope probe returns no result instead of fabricated content.
